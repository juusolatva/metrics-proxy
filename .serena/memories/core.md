# metrics_proxy — core

HTTP reverse proxy between LLM clients and a local LLM server (LM Studio primary; Ollama and other OpenAI-compatible servers also targeted); extracts per-request inference metrics (tokens, TPS, duration, model) and prints them to stdout.

## Source map
- `main.go` — entire app (single `package main`): config (`loadConfig`, `parseConfig` with defaults), startup banner backend probe (`detectBackend`), server (`runProxy`, `serve` with graceful shutdown driven by `stop`/`force` contexts created in `main` (with `defer cancel()`) and cancelled by `setupSignalHandling(onFirst, onSecond)`, `handleRequest`), forwarding (`newReverseProxy`, `meterResponse`), body inspection (`meteredBody`, `newCapture` → `jsonCapture` / `sseCapture` / `ndjsonCapture`, streaming ones share `lineSplitter`), payload parsing (`llmPayload`, `MetricsData.merge`), aggregation (`updateGlobalMetrics`), terminal output (`displayMetrics`), CSV output (`--csv` flag → `openCSVLog` / `csvRecorder`, global `csvLog`).
- `main_test.go` — httptest tests; `startUpstream` starts a fake upstream, `startProxy` resets globals and starts the proxy, `startServe` drives `serve()` with test contexts.
- `testdata/` — real captured response bodies: `lm_*` LM Studio, `ol_*` Ollama. Recaptured on 2026-10-17 (12 files, committed; `.gitattributes` sets `testdata/** -text`). LM Studio `qwen/qwen2.5-coder-14b` with speculative decoding (draft 0.5B; intended, user wants it tested), Ollama `qwen3:4b-instruct-2507-q8_0`. Prompt `Count from 1 to 5, separated by spaces.`. Covers /api/v1/chat, /v1/chat/completions (JSON, stream with/without include_usage), Ollama /api/chat, /api/generate. Read via `readFixture()` (fails if missing). Old captures are in git history (`eed1e06`).

## Invariants / gotchas
- Package-level globals: `cfg`, `proxy`, `metrics`, `out` (status-line writer, swapped in tests), `csvLog` (nil unless `--csv`; reset in `startProxy`).
- `--csv` is a command-line flag, not a `config.yaml` key. `recordQuery` writes one row per counted query (same filter as the status line). The `csvRecorder` has its own mutex and flushes every row. The header (`csvHeader`) is written only to an empty file. Unknown values are empty, not 0. Changing columns breaks appending to existing files: add new columns at the end.
- CSV method/path/model text uses `csvText` to prefix a protective apostrophe when needed (formula prefixes including fullwidth and leading whitespace/control/format variants, initial controls, invalid UTF-8). Other text is unchanged; quoting still handles CSV delimiters. Existing CSV rows are not rewritten: use a new export or import old columns as text. In-memory metrics and response forwarding retain raw values.
- `metrics.mu` (RWMutex) guards all `Metrics` fields; never hold it across network I/O.
- Command-line flags: document and show them as GNU-style `--name` (user preference; `flagUsage` prints help that way). Go's `flag` package accepts both `-name` and `--name`, so no parsing change is needed.
- Config parsing is strict (`decodeConfig()`: `yaml.NewLoader` with `WithKnownFields()`, `WithUniqueKeys()`): unknown or misspelled keys, duplicate keys and a second YAML document are errors with line numbers (`TestParseConfigRejectsUnknownKeys`, `TestParseConfigYAMLRules`). New options must be optional with defaults. Removing or renaming a key breaks files that use it; the user accepted that for unused settings (2026-10-17). Defaults: port 11436 (user's choice 2026-10-17, was 8080: avoids 8080 and Ollama's 11434 plus a second instance on 11435), upstream localhost:1234, `api_endpoints` `/api/v1/*` + `/v1/*` (also when empty), `forward_unmatched` true (`*bool`, read via `cfg.forwardsUnmatched()`), `allowed_hosts` empty, `history_points` 10. `api_endpoints` only selects which paths are metered; other paths are forwarded unmetered with a `[Proxy] … (Ns, not metered)` line, or 404'd without forwarding when `forward_unmatched: false`. The user asked for this to be configurable after clients' `GET /models` got the proxy's own 404. An empty file is valid.
- `forward_management` (plain `bool`, default false; security fix 2026-10-24): the proxy listens on all interfaces without auth (user's clients are on other LAN machines, keep it that way), so `handleRequest`, right after the Host check, calls `refuseManagement()`, which answers 403 without forwarding for `managementEndpoints` (Ollama pull/push/create/copy/delete/blobs, account `/api/me`, `/api/signout`, `/api/user/keys`; LM Studio `/api/v1/models/load|unload|download`; matched by `isManagementEndpoint()` after `path.Clean` + lowercase, exact or below) and for any `Upgrade` header offering a protocol other than `h2c`, on any path (`offersUpgrade()`; tunnels bypass the check, and LM Studio's SDK loads/downloads models over WebSocket on `/llm`, `/repository`, ...). An h2c-only offer (Java `HttpClient`) is deleted so the request goes out as plain HTTP/1.1. Ollama web search/fetch are deliberately not listed (account queries, like cloud models). Refused even when the path matches `api_endpoints`. Tests: `TestManagementEndpointNotForwarded`, `TestUpgradeNotForwarded`, `TestManagementForwardedWhenEnabled`.
- DNS rebinding guard: `handleRequest` first runs `allowedHost(hostName(r.Host))` and answers `403` + `[Proxy] Rejected …` (Host via `%q`) without forwarding. Needed because `pr.SetURL` replaces Host, so the upstream's own check (Ollama `allowedHostsMiddleware`) always passes. Accepted: empty, any IP literal, `localhost`, `localSuffixes` (`.localhost`, `.local`, `.internal`, `.home.arpa`), `os.Hostname()`, `allowed_hosts` (exact, `*.domain`, `*` = off). `.lan` deliberately not built in (not reserved). User's LAN clients use the IP (and maybe the hostname), so both must keep working. httptest clients send `Host: 127.0.0.1:<port>` (accepted).
- All config keys are implemented. `metrics.mode` and `refresh_interval_ms` were removed and are now rejected as unknown keys.
- `logging.debug` → `debugf()` writes `[DEBUG] req N: …` lines to `out` (request ID from `requestSeq`). Per-body summary in `meteredBody.debugSummary()`: EOF, bytes, the capture's `captureDiag` (each capture implements `diag()`), TPS basis returned by `completeDerived()`, and the `include_usage` hint. `mergeJSON` returns whether the document was a JSON object (a whole-document `UnmarshalTypeError` with `Field == ""` counts as invalid). Never log bodies.
- Flags are parsed by `parseFlags(args, output)` on its own `FlagSet` (`ContinueOnError`; returns `flag.ErrHelp` for `--help`). Flags: `--config`, `--csv`. Positional args are rejected (exit 2). Add new flags there and cover them in `TestParseFlags`.
- Response bodies are streamed via `httputil.ReverseProxy` and inspected through a `meteredBody` wrapper (set in `ModifyResponse`); metrics are recorded when the body ends, on the proxy goroutine — after or racing with the client finishing its read. Never read the body in `ModifyResponse` (blocks headers, breaks SSE).
- Upstream payload shapes differ per API: OpenAI-compat `/v1/*` (`model`, `usage.*`), LM Studio native v1 `/api/v1/*` (`model_instance_id`, `stats.{input_tokens,total_output_tokens,tokens_per_second,time_to_first_token_seconds}`; streamed `chat.end` wraps it in `result`), v0 (`usage` + `stats.time_to_first_token`). Source: lmstudio.ai/docs/developer/rest.
- Ollama shapes: native `/api/chat|generate` → `prompt_eval_count`, `eval_count`, `eval_duration` (ns), streamed as `application/x-ndjson` (final line `done:true` holds stats); OpenAI-compat SSE reports TPS only in `timings.predicted_per_second`. TPS = `eval_count / eval_duration`.
- `mergeJSON` tolerates `json.UnmarshalTypeError` (keeps other fields); `result`/`response` stay `json.RawMessage` (Ollama `/api/generate` `response` is a string).
- `mergeJSONBounded` limits inspection to 8 wrapper hops and 32 MiB cumulative decode bytes per JSON body/SSE event/NDJSON line, shared across `result` and `response` siblings and checked before decoding. `merge` applies one payload's fields only. Keep parent → result → response precedence and retain already read fields when a limit skips deeper wrappers. Response forwarding is unaffected; the 16 MiB capture bound is separate.
- Config key `server` (`Config.Server`, `ServerConfig`) names the upstream for any server type. It was `lm_studio` until 2026-10-17; the user had it renamed without an alias, as they are the only user so far and want no backward-compat shims.
- Responses without model/tokens/TPS are not counted as queries.
- Shutdown: the first SIGINT/SIGTERM triggers `server.Shutdown`, waiting up to `shutdownTimeout` (60 s) for in-flight streams. A second signal or the timeout triggers `server.Close`, and cut-off queries are logged `incomplete`. Exit status is 0 either way. Test `serve` via the `startServe` helper with your own contexts, not real signals.
- TPS not reported by the upstream is derived in `completeDerived`, which sets `MetricsData.TPSEstimated`; the status line shows `(est.)`. LM Studio OpenAI-compat (`/v1/*`, streamed or not) never reports a rate: `stats` is empty or, with speculative decoding, holds only draft counters. So its TPS is always estimated (non-streamed: badly understated for short replies).
- TTFT comes only from LM Studio native `/api/v1/*`; Ollama (native + OpenAI-compat) and LM Studio OpenAI-compat don't report it, so no `TTFT` field for them.
- LM Studio answers unknown endpoints with HTTP 200 + `{"error":...}` (Ollama: 404). Never identify the server by status code; `detectBackend` checks for a known JSON key per probe.
- Verified live on 2026-10-17 against LM Studio and Ollama (all native/OpenAI-compat endpoints, streamed and not). Not yet run on Windows (cross-compiles; checklist in `docs/windows-testing.md`).
- `proxyError` answers 502 "Failed to connect to the upstream LLM server". User-facing text and config keys must not assume LM Studio (banner, errors, `server` key).
