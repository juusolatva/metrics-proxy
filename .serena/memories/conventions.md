# Conventions

- Stdlib first; justify any new dependency.
- Single-file layout today (`main.go`); splitting into more files within `package main` is fine, keep it one module.
- Exported identifiers with short `// Name does …` doc comments; YAML fields mapped via `yaml:"snake_case"` struct tags.
- Logging: per-request lines go through `fmt.Fprintf(out, …)` (`out` = stdout, swapped in tests) with bracketed prefixes `[Proxy]`, `[ERROR]`, `[DEBUG]` (only via `debugf()`); query status lines have no prefix. Startup banner/errors use `fmt.Printf`. No logger package. Client/upstream text (paths, request URIs, URLs, model names, upstream errors) is printed via `escapeControls()` (Go escapes for control chars, invalid UTF-8, U+2028/U+2029, bidi controls; other text unchanged); `debugf` calls that escape are wrapped in `if cfg.Logging.Debug` because arguments are evaluated even when debug is off. CSV keeps raw values.
- Errors: golangci-lint `errcheck` applies to non-test code (`.golangci.yml`; `std-error-handling` preset exempts `Close`, `fmt.Fprint*` …). Deliberately ignored errors are discarded explicitly with a reason comment (`_ = r.w.Write(row) // write errors are sticky…`), not `//nolint`. Exception: discarded `<-errc` (chan error) in `serve()` keeps `//nolint:errcheck`; `_ = <-errc` trips staticcheck S1005.
- Concurrency: write-lock `metrics.mu` for updates, read-lock for display; copy data out rather than holding locks during I/O.
- Tests: every bug fix/feature gets `httptest`-based tests (fake upstream server + `httptest.NewRecorder`/`NewServer`); must pass under `-race`. Tests touching globals (`cfg`, `metrics`, `out`, `csvLog`) must reset them (`startProxy` does). Keep every function, tests included, at cognitive complexity ≤ 15 (SonarCloud `go:S3776`, see `mem:sonarcloud`): table-driven loops call a named `check…` helper.
- Parser tests: prefer real captures in `testdata/` (`<upstream>_<api>[_stream][_variant].<ext>`, e.g. `ol_oai_stream_nousage.sse`) over hand-written JSON. They are read with `readFixture()`, fed whole and in 1-byte chunks (`TestCaptureFixtures`), and committed. New upstream/endpoint support → capture JSON + streamed fixtures first (directly from the server, body only). Before capturing, show the user every request (server, model, body) and what gets saved, and wait for approval (user requirement); check captures for private data.
- Proxy must not buffer whole responses before forwarding (breaks SSE streaming); inspect bodies via tee while streaming to client.
- New config options need sane zero-value defaults so existing files keep working. Parsing is strict, so removing or renaming a key breaks files that use it (acceptable for unused settings; note it in README.md).
